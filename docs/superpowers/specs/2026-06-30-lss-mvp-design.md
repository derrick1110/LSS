# 极简记账 MVP 设计

日期：2026-06-30

## 目标

极简记账的 MVP 目标是让用户在付款后 3 秒内完成一笔支出记录。MVP 不追求全自动读取支付宝或微信通知，因为 iOS 快捷指令无法稳定读取任意 App 推送通知正文。第一版采用稳定的一键快捷指令流程：用户从锁屏、控制中心或主屏触发快捷指令，输入金额后唤醒 App，App 自动落库并进入今日页。

## 范围

MVP 包含：

- 快捷指令输入金额后通过 URL Scheme 唤醒 App。
- App 校验金额并自动创建支出记录。
- 快捷指令入账默认分类为餐饮。
- 分类固定为餐饮、日用、其他三类。
- 今日页展示今日总额、分类占比和今日流水列表。
- 支持手动补记、编辑和删除流水。
- 数据完全本地存储，不做账号、云同步和多设备同步。

MVP 不包含：

- 自动读取支付宝或微信通知正文。
- OCR 识别截图或账单。
- 预算系统。
- 分类自定义。
- 收入、转账、资产账户管理。
- 去重 requestId。

## 技术路线

使用 SwiftUI + SwiftData 开发原生 iOS App，最低支持 iOS 17。MVP 采用纯本地离线架构，所有交易记录保存在本机 SwiftData 存储中。

选择 SwiftData 的原因：

- 数据模型简单，适合快速完成 MVP。
- 与 SwiftUI 集成自然。
- 用户当前核心目标是个人本地使用，不需要优先引入云端或跨端复杂度。

## 核心流程

快捷指令流程：

1. 用户付款完成。
2. 用户从锁屏、控制中心或主屏触发快捷指令。
3. 快捷指令弹出输入框，要求输入本次消费金额。
4. 快捷指令打开 URL：`lss://record?amount=12.5`。
5. App 被唤醒并解析 URL。
6. App 校验金额。
7. App 创建支出记录，默认分类为餐饮。
8. App 跳转到今日页，并将新记录置顶展示。

App 内补记和纠错流程：

1. 用户打开今日页。
2. 点击右上角新增入口可手动补记。
3. 点击流水可进入编辑页修改金额、分类、备注或时间。
4. 左滑流水可删除记录。
5. 修改或删除后，今日总额和分类占比立即刷新。

## 数据模型

MVP 只需要一个核心实体：`Transaction`。

字段：

```text
id: UUID
amount: Decimal
type: expense
category: food | daily | other
note: String?
source: shortcut | manual
createdAt: Date
updatedAt: Date
```

分类展示映射：

```text
food  -> 餐饮
daily -> 日用
other -> 其他
```

说明：

- MVP 只记录支出，`type` 固定为 `expense`。
- 快捷指令入账的 `source` 为 `shortcut`。
- App 内手动补记的 `source` 为 `manual`。
- 分类在 MVP 不独立建表，使用枚举或字符串常量。

## 页面结构

### 今日页

今日页是 App 默认首页，也是快捷指令成功落库后的目标页。

内容：

- 今日总额。
- 三分类占比：餐饮、日用、其他。
- 今日流水列表，按时间倒序排列。
- 右上角新增入口。
- 点击流水进入编辑页。
- 左滑删除流水。

行为：

- 快捷指令新增的记录应出现在列表顶部。
- 刚新增的记录高亮 1.5 秒，帮助用户确认已经记上。
- 删除或编辑后，今日总额和分类占比立即刷新。

### 编辑/补记页

编辑和补记共用一个表单。

字段：

- 金额，必填，必须大于 0。
- 分类，必选，三选一：餐饮、日用、其他。
- 备注，可选。
- 时间，默认当前时间。

行为：

- 新增模式显示保存入口。
- 编辑模式显示保存和删除入口。
- 金额非法时不保存，并提示用户修正。

## URL Scheme

App 注册 URL Scheme：

```text
lss://record
```

MVP 支持参数：

```text
amount=12.5
category=food   可选，默认 food
source=shortcut 可选，默认 shortcut
```

示例：

```text
lss://record?amount=12.5
lss://record?amount=8&category=daily
```

解析规则：

- `amount` 必须存在，且必须是大于 0 的数字。
- `category` 只接受 `food`、`daily`、`other`；缺失或非法时按 `food` 处理。
- `source` 只接受 `shortcut`、`manual`；缺失时按 `shortcut` 处理。
- MVP 不做重复 URL 去重。

## 错误处理

URL 缺少 `amount`：

- 不落库。
- 打开手动补记页。

`amount` 不是数字：

- 不落库。
- 打开手动补记页。
- 提示“金额格式不正确”。

`amount <= 0`：

- 不落库。
- 打开手动补记页。
- 提示“金额必须大于 0”。

`category` 非法：

- 不阻断记账。
- 按 `food` 记录为餐饮。

原则：

- 金额错误会污染账本，因此必须阻断。
- 分类错误可以晚上纠正，因此不阻断极速记账流程。

## 测试策略

URL Scheme 测试：

- `lss://record?amount=12.5` 能新增餐饮记录。
- `lss://record?amount=8&category=daily` 能新增日用记录。
- `amount=0` 不新增记录，并进入补记页。
- `amount=abc` 不新增记录，并进入补记页。
- `category=bad` 能新增餐饮记录。

今日页测试：

- 今日总额等于今日流水金额之和。
- 分类占比只统计餐饮、日用、其他。
- 新增记录后列表置顶展示。
- 删除记录后今日总额和分类占比立即刷新。
- 修改金额或分类后今日总额和分类占比立即刷新。

编辑页测试：

- 可以新增一笔手动记录。
- 可以修改金额。
- 可以修改分类。
- 可以修改备注。
- 备注可以为空。
- 可以删除已有记录。
- 金额为空、非数字或小于等于 0 时不能保存。

## 后续扩展

MVP 验证通过后，可以按以下顺序扩展：

1. 快捷指令支持可选分类参数或常用金额快捷入口。
2. 增加预算进度。
3. 增加月视图和简单趋势统计。
4. 增加截图 OCR 或账单文本解析。
5. 增加 iCloud 同步。
6. 增加 requestId，避免重复 URL 导致重复入账。
